# Public offer HTTP and directions verification — 2 October 2026

The public application endpoints passed **seven real HTTP/Auth/MFA/RPC/SQL cases** on the contained Next development app and disposable patched clone. [Successful evidence](pinpoint-offer-public-http-local-evidence.json) is separate from the [13-case projection rehearsal](pinpoint-offer-public-read-verification.md). No customer screen or complete category journey is claimed by this checkpoint.

`GET /api/offers?areaId=…` and `/api/offers/count?areaId=…` use the same read-time eligible projection. `GET /api/offers/[id]` returns live or scheduled records, a content-free 410 for an expired approval, or a minimal 404 for unavailable/unknown records. Requests with missing, repeated, unexpected or incomplete query inputs return 400. All responses disable caching. The application adapter uses only the anonymous key and no persisted session or private table access.

`GET /api/offers/[id]/directions` rechecks current eligibility before redirecting. A live response uses the fixed Google Maps directions host, `api=1` and the exact reviewed shop latitude/longitude. It sends no visitor origin, contact details or private account ID. The response suppresses referrer information. The format follows [Google's directions URL documentation](https://developers.google.com/maps/documentation/urls/get-started#directions). Tests captured 302 headers with redirect following disabled; no external map was opened. This establishes link construction and eligibility, not arrival or redemption.

Observed cases covered strict public input validation; empty/pending/unknown states; actual MFA approval through the anonymous server adapter; private saves excluding draft text; catalogue drift and admin unpublication blocking old action links; actual scheduled/live/expired HTTP transitions with schedules paused; and controlled database permission denial returning a safe 503 without diagnostics or redirect. The handler also subtracts the entire monotonic RPC duration from database-reported remaining validity before redirecting. A focused test denies a reply whose elapsed time consumes its remaining window, without relying on synchronized app/DB wall clocks.
