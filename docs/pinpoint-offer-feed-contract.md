# Shopping Offer Feed contract — 2 October 2026

The additive `/offers` page uses an app-owned areaId and optional complete server cursor. With no area it asks for a location and reads no offer data. Invalid/repeated/unknown identifiers do not manufacture a named area or empty supply. The place label/address come from the stored catalogue, not caller-supplied text. A place with no currently eligible offers remains selectable and displays a truthful empty state.

The public place adapter uses an anonymous, read-only client with explicit public columns and the existing catalogue SELECT/RLS grants. It carries no cookie or service credentials, creates no place and changes no grant or policy. `/api/offers/places?q=...` has one bounded search parameter, a six-result limit, stable name/ID ordering, literal wildcard escaping and no-store responses. A database failure produces 503, not an empty result. This catalogue-only lookup is useful without a map/geocoder key; it does not close South Africa-wide live-geocoder/catalogue coverage or provenance acceptance.

The Feed reuses the common public eligibility/count/cursor projection. It displays at most twenty confirmed, currently live rows, links to stable detail, and has a Next offers link when the server supplies a cursor. Count copy states when it was checked in SAST. New location selection starts at the first page. Old requests are aborted and ignored on unmount/context changes; wrong-area replies are rejected. Failed reads hide stale rows and display retry. Refresh replaces the current page, rather than appending stale snapshots.

Visible pages refresh periodically and at the earliest returned offer end time, using conservative DB-relative/monotonic timing. At a known end boundary old rows/count are hidden while a fresh eligibility query runs. Delayed replies that have already crossed a returned end boundary are refetched. This does not depend on cron. A detail or directions action still performs its own fresh eligibility checks. Feed counts are exact database snapshots, not a promise that other unseen offers cannot change between checks.

The Property link carries the stored UUID, canonical address and existing view=feed URL contract. Existing Property links/listingId/saved homes/rent-buy filters are not modified. A common four-category navigation and preservation of category-specific filter state remain later work. The Feed loads no map component and asks for no geolocation. Image-free offer rows show title, benefit, shop/public address and SAST end date; full terms remain on detail. No private draft or admin evidence is added to the public DTO. Metadata stays noindex pending complete customer/release acceptance.
