# Admin permission evidence — 2 October 2026

Private admin permission evidence is implemented and passes **13 real Auth/MFA/HTTP/browser/SQL checks on a disposable patched clone**. This records a check of supplied authorization for the exact pending revision; it neither approves nor publishes an offer. Release 1 remains 2/48 complete.

## Change

Migration `20261002023000_pinpoint_offer_permission_review.sql` adds immutable evidence records containing the request ID, offer/revision/poster, actual Auth reviewer, captured offer version, evidence kind, private reference/note, attestation version and database time. Direct reads and writes are revoked, including service-role access. Current-MFA session RPCs provide the bounded pending-revision read/write path. The original schema, lifecycle, intake adapter/migration/functions and existing grants/policies remain unchanged.

The writer checks active reviewer membership/account/session, policy acceptance and real aal2, with the existing admin one-factor and owner two-factor thresholds. It locks the offer and rechecks gates, exact revision/version, withdrawal and durable poster eligibility. Poster permission must exist for that exact revision. The poster need not remain logged in while a reviewer checks it; confirmed permanent account, capability, suspension/ban and required policy acceptance still apply. A repeated identical request ID deduplicates; different content cannot overwrite that record. Evidence adds no offer version or public status change. Historical evidence stays with its original revision.

The cookie API validates same-origin JSON and bounded input, rejects actor/time flags, returns private/no-store responses and maps conflicts/access failures without exposing database details. The screen shows the exact poster confirmation and private reference/note. A 409 preserves unsaved text and locks the captured version; evidence edits clear the checkbox. On success, it explicitly says the offer remains private. The server compares the content and permission snapshots before presenting both forms, avoiding a mixed-revision review if the offer changes during loading. Correction/rejection remains available.

## Observed proof

- Anonymous and all aal1 actors were denied. Real one-factor admin aal2 read/wrote the exact consent; a revision without consent could not receive evidence.
- Missing/false attestation, outdated version, blank reference/note and substitution of a public shop page as authorization were rejected. Stale offer versions returned 409 without a record.
- SQL verified actual reviewer/revision/version/time, unchanged offer version/pending pointer, idempotent retry and rejection of an altered retry. Privileged SQL UPDATE was denied by the immutable trigger.
- Direct table reads/inserts/updates/deletes were denied; session RPC reads required current MFA. Same-token membership revocation, poster suspension and reviewer suspension blocked operations without extra records.
- Owner aal2 with one verified TOTP was denied; two genuinely enrolled/verified factors permitted access. Rejection and fresh submission retained old evidence history without copying it to the new revision.
- Real browser password sessions were denied at aal1 and passed an actual TOTP challenge. Desktop HTTP 409 retained the note/reference; desktop and phone owner form writes persisted, survived reload and left the offer pending/private. Phone had no horizontal overflow. Browser errors and outside destinations were empty in the successful run.
